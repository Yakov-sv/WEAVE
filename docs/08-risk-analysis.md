## Детальная митигация по топ-5 рискам

### Риск 1: Сетевой эффект не запускается (P=3, I=3)

**Симптомы:** Регистрации есть, но MAU не растёт, пользователи не возвращаются.

**Митигация:**
- Beachhead-стратегия: одна ниша (разработчики), одно ценное действие (Git + лента)
- OSS-программа: бесплатные Pro-аккаунты для open-source проектов → органический трафик
- Импорт из GitHub/Telegram: миграция с сохранением данных → мгновенная ценность
- Реферальная программа: early access за 3 реферала → вирусный рост
- "Один большой пользователь": партнёрство с крупным dev-инфлюенсером (100K+ audience)

**Триггер эскалации:** MAU < 500 на месяце 4 → pivot ниши или модели

### Риск 2: GitHub добавляет мессенджер/монетизацию (P=2, I=3)

**Симптомы:** GitHub анонсирует встроенный чат, расширяет Sponsors, добавляет ленту.

**Митигация:**
- GitHub — enterprise-компания, медленно инновирует (GitHub Discussions waited 5 years)
- WEAVE фокусируется на монетизации (GitHub Sponsors — донаты, не подписки/маркетплейс)
- WEAVE — для B2C/криэйторов, GitHub — для B2B/инженеров
- Если GitHub двигается → WEAVE становится "для криэйторов, не для инженеров"

**Триггер эскалации:** GitHub запускает платные каналы → ускорить фазу 2 (Creator expansion)

### Риск 3: Сложность продукта / UX-перегруз (P=2, I=3)

**Симптомы:** Пользователи не понимают, что делать, высокий bounce rate, жалобы на сложность.

**Митигация:**
- Progressive disclosure: стартуем с одной функции (Feed), раскрываем остальные по запросу
- Onboarding-визард: "Что вы хотите делать?" → активируем нужные модули
- "Простой режим" (только лента + чаты) и "Pro режим" (все модули)
- A/B-тестирование UX на alpha-группе
- Каждый модуль — отдельный раздел с чистым UX

**Триггер эскалации:** bounce rate > 60% на onboarding → редизайн

### Риск 4: Стоимость инфраструктуры (P=2, I=3)

**Симптомы:** Расходы на инфраструктуру растут быстрее дохода.

**Митигация:**
- Gitea (self-hosted, лёгкий) вместо своего Git-движка
- MinIO (self-hosted S3) вместо AWS S3 на старте
- PostgreSQL для всего (включая FTS и pgvector) → минимум сервисов
- CDN только для медиа (не для кода)
- Кэширование (Redis) для снижения нагрузки на БД
- Serverless для background jobs (если выгодно)

**Триггер эскалации:** Инфра > $5K/мес при < $10K MRR → оптимизация

### Риск 5: Высокий churn на старте (P=3, I=2)

**Симптомы:** Day-7 retention < 20%, пользователи регистрируются и не возвращаются.

**Митигация:**
- Email-рассылки после регистрации (day 1, 3, 7)
- "Aha moment" в первые 5 минут: импорт из GitHub → мгновенная лента
- Push-уведомления (PWA) для новых постов/сообщений
- Gamification: badges за первые действия
- Личные онбординг-сессии для первых 500 пользователей

**Триггер эскалации:** Day-7 retention < 15% → полный редизайн onboarding

## План непрерывности (Business Continuity)

| Сценарий | План |
|---|---|
| Падение основного дата-центра | Multi-AZ deployment, бэкапы каждые 6 часов, RTO < 4ч |
| Блокировка платёжного провайдера | Резервный провайдер (крипто-платежи), escrow |
| Уход ключевого сотрудника | Documentation-first, bus factor > 2 на каждый модуль |
| DDoS-атака | Cloudflare (free tier → Pro), rate-limiting, autoscaling |
| Утечка данных | Bug bounty, security audit, GDPR-compliant incident response |
