# WEAVE — Техническое задание на MVP

## 1. Цель MVP

Создать минимально жизнеспособный продукт, валидирующий гипотезу: разработчики готовы использовать единую платформу для ленты (как X), каналов (как Telegram), Git-репозиториев (как GitHub) и платных подписок.

## 3. Out of Scope MVP (что НЕ входит)

| Функция | Фаза | Причина |
|---|---|---|
| Stories / Reels | Фаза 2 | Медиа-формат — не для разработчиков в MVP |
| Видео в постах | Фаза 2 | Требует CDN-транскодинг |
| Алгоритмическая лента | Фаза 2 | Нужен объём данных для алгоритма |
| E2E-шифрование DM | Фаза 2 | Сложная криптография, не критично для MVP |
| Маркетплейс (листинги) | Фаза 2 | Фокус на подписках в MVP |
| Эскроу | Фаза 2 | Юридическая сложность |
| Web code editor | Фаза 2 | Monaco интеграция — большой объём работы |
| Pull Requests (полные) | Фаза 1 (P1) | Базовый просмотр в MVP, полный merge в фазе 2 |
| Issues (полные) | Фаза 1 (P1) | Базовые в MVP, labels/milestones в фазе 2 |
| Voice rooms | Фаза 3 | Требует LiveKit/WebRTC |
| Plugin SDK | Фаза 3 | Нужна зрелая платформа |
| Мобильное приложение | Фаза 3 | PWA достаточно для MVP |
| Federation (ActivityPub) | Фаза 4 | Децентрализация — не для MVP |
| B2B / Team spaces | Фаза 3 | Фокус на индивидуальных пользователях |
| Крипто-платежи | Фаза 2 | Stripe достаточно для MVP |
| Multi-language UI | Фаза 3 | EN-only для MVP |

## 4. User Stories

### Identity

```
US-001: Как новый пользователь, я хочу зарегистрироваться по email,
чтобы создать профиль на WEAVE.

US-002: Как пользователь, я хочу войти через passkey,
чтобы не запоминать пароль.

US-003: Как пользователь, я хочу редактировать свой профиль
(аватар, bio, имя), чтобы представиться сообществу.

US-004: Как пользователь, я хочу подписаться на другого пользователя,
чтобы видеть его посты в ленте.

US-005: Как пользователь, я хочу привязать свой GitHub-аккаунт,
чтобы импортировать репозитории.
```

### Feed

```
US-010: Как пользователь, я хочу создать пост с текстом и markdown,
чтобы поделиться мыслью с подписчиками.

US-011: Как пользователь, я хочу прикрепить изображение к посту,
чтобы показать скриншот или визуал.

US-012: Как пользователь, я хочу видеть ленту постов от моих подписок,
чтобы быть в курсе обновлений.

US-013: Как пользователь, я хочу ответить на пост,
чтобы начать обсуждение.

US-014: Как пользователь, я хочу лайкнуть пост,
чтобы выразить одобрение.

US-015: Как пользователь, я хочу сохранить пост в закладки,
чтобы вернуться к нему позже.
```

### Messaging

```
US-020: Как пользователь, я хочу написать личное сообщение другому пользователю,
чтобы обсудить что-то приватно.

US-021: Как пользователь, я хочу создать канал,
чтобы вещать для подписчиков.

US-022: Как автор канала, я хочу сделать канал платным,
чтобы зарабатывать на эксклюзивном контенте.

US-023: Как пользователь, я хочу подписаться на платный канал,
чтобы получить доступ к контенту.

US-024: Как пользователь, я хочу получать сообщения в реальном времени,
чтобы общаться без задержек.
```

### Git

```
US-030: Как разработчик, я хочу создать репозиторий,
чтобы хостить свой код.

US-031: Как разработчик, я хочу импортировать репозиторий из GitHub,
чтобы мигрировать без потери данных.

US-032: Как разработчик, я хочу просматривать файлы репозитория в браузере,
чтобы читать код без клонирования.

US-033: Как разработчик, я хочу клонировать репозиторий через SSH/HTTPS,
чтобы работать с кодом локально.

US-034: Как разработчик, я хочу поставить звёздочку репозиторию,
чтобы отметить интерес.

US-035: Как автор, я хочу сделать репозиторий платным,
чтобы продавать доступ к коду по подписке.
```

### Market / Payments

```
US-040: Как автор, я хочу создать платный канал,
чтобы зарабатывать на подписке.

US-041: Как подписчик, я хочу оплатить подписку картой,
чтобы получить доступ к контенту.

US-042: Как автор, я хочу видеть свой баланс,
чтобы знать, сколько заработал.

US-043: Как автор, я хочу вывести средства на банковский счёт,
чтобы получить деньги.

US-044: Как подписчик, я хочу отменить подписку,
чтобы не платить дальше.

US-045: Как пользователь, я хочу отправить чаевые автору,
чтобы поддержать его.
```

## 6. Acceptance Criteria для MVP

### Критерии готовности MVP

- [ ] Пользователь может зарегистрироваться, создать профиль, загрузить аватар
- [ ] Пользователь может подписаться на других пользователей
- [ ] Пользователь может создать пост (текст + изображение)
- [ ] Пользователь видит ленту постов от подписок
- [ ] Пользователь может лайкнуть, ответить, сохранить пост
- [ ] Пользователь может отправить DM другому пользователю
- [ ] Пользователь может создать канал и публиковать посты
- [ ] Автор может сделать канал платным (Stripe checkout)
- [ ] Пользователь может подписаться на платный канал (оплата картой)
- [ ] Пользователь может создать репозиторий (public/private)
- [ ] Пользователь может импортировать репозиторий из GitHub
- [ ] Пользователь может просматривать файлы репозитория в браузере
- [ ] Пользователь может клонировать репозиторий через SSH/HTTPS
- [ ] Пользователь может поставить звезду репозиторию
- [ ] Автор может сделать репозиторий платным
- [ ] Автор видит баланс и может запросить выплату
- [ ] Сообщения доставляются в реальном времени (WebSocket)
- [ ] Уведомления приходят в реальном времени
- [ ] PWA устанавливается на Android/iOS
- [ ] Lighthouse score > 80 (performance, a11y, SEO)

### Критерии успеха MVP (через 3 месяца после launch)

- 1 000+ активных пользователей (MAU)
- 100+ созданных репозиториев
- 50+ созданных каналов
- 10+ платных подписок
- Day-7 retention > 25%
- NPS > 40
